# Momo Upload Retention

Migration012 implements durable tickets before signing, atomic registration/quota using actual provider upload time+72h, cleanup leases/tombstones, account/source deletion responsibility and backlog monitoring. Existing registration replay checks expiry and cleanup ownership. New unticketed registration fails closed. Generated study material persists independently. Migrations012–013 and 018 are applied on the authorized `momo-staging`; its ticket and app tables were empty at the preceding inspection. Migration013 adds a partial `auth_ref` lookup index so Auth deletion cleanup can target live tickets.

Migration018 closes the signed-upload resurrection race for explicit source/account deletion: physical purge is not claimable until `signed_until + 15 minutes`, any earlier cleanup lease is revoked, and the prepare RPC independently checks the deadline. `DELETE /api/documents/{id}` removes the source and chunks from the library now, while the worker retains the durable ticket and retries physical cleanup after the deadline. The UI confirmation explains this timing. The API and storage behavior have local tests; staging verification is catalog-only because no hosted synthetic Auth user/object was created.

Automatic physical deletion must target the observed generation. Local mocks compare metadata atomically; S3 requires a VersionId. Supabase's current JavaScript reference documents exact-version removal with `{path, versionId}`. The app pins Python `storage3` 2.31.0, and a fresh inspection of the published 2.32.0 wheel found both sync and async `remove()` still accept only path strings. Supabase's S3 guide says bucket versioning is unsupported, and the selected bucket behavior remains unverified. Automatic expiry therefore stays fail-closed; do not use path-only deletion. Resolve this SDK/provider gate, legacy and unregistered inventory, scheduler timing and measured capacity before public launch. No hosted Storage calls were made for this audit.

Legacy tickets have unverified provider/bucket and historical clocks; they remain visible for explicit inventory/backfill. Confirmed absence is recorded while tombstones retain15-minute probes for late/recreated bytes. Provider outages are never absence.
